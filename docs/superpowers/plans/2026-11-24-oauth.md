# OAuth Sign-in Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Let MCP clients (Grok Bot, Claude Code) get and renew their own credentials through standard MCP OAuth, approved by the owner's Google sign-in, alongside the existing fixed tokens.

**Architecture:** The SDK's `mcpAuthRouter` serves discovery, registration, `/authorize`, `/token` and `/revoke`. Our `OAuthStore` keeps clients and grants (token hashes only) in `DATA_DIR/oauth-state.json`; our `GscOAuthProvider` holds short-lived sign-in state in memory and sends the owner through Google and a consent page. `bearerAuth` accepts a fixed token or an OAuth access token; a `/clients` page lists and revokes grants.

**Tech Stack:** TypeScript (strict, ESM, `.js` import suffixes), Express 5, `@modelcontextprotocol/sdk` 1.32.2 (`server/auth/*`), `google-auth-library` 11.3.3 (`OAuth2Client`), zod 4, vitest 5.

**Spec:** `docs/superpowers/specs/2026-11-24-oauth-design.md`

## Global Constraints

- Base branch: `auth-multi-token` must be committed first; work happens on branch `oauth` created from it.
- Commits: the user's CLAUDE.md says commit only when asked. The commit steps below run only after the user has approved committing for this plan; otherwise leave changes uncommitted and report.
- No new npm dependencies. Use `google-auth-library` (direct dependency) and the SDK's auth modules.
- Never log or persist a token, code, client secret or Google ID token. Persist only SHA-256 hashes (hex).
- Constants (one place, `src/oauth/store.ts` unless noted): `ACCESS_TOKEN_TTL_MS = 3_600_000`; `PENDING_TTL_MS = 300_000` (authorization requests, Google state, consent, codes; in `provider.ts`); `UNUSED_CLIENT_TTL_MS = 86_400_000`; `MAX_CLIENTS = 100`; `LAST_USED_FLUSH_MS = 60_000`; `CLIENT_NAME_MAX = 64`; `SESSION_TTL_MS = 43_200_000` (in `routes.ts`).
- Grant expiry: 00:00 UTC on (approval day + `MCP_AUTH_TOKEN_TTL_DAYS`), always applied, independent of `MCP_AUTH_AUTO_EXPIRE`.
- Log label for an OAuth client: `oauth:<name>#<first 6 chars of grant id>`.
- Paths: `/oauth/google/callback`, `POST /oauth/consent`, `GET /clients`, `POST /clients/revoke`, `POST /clients/revoke-all`, `POST /clients/sign-out`. Session cookie `gsc_mcp_session`: `HttpOnly; Secure; SameSite=Lax; Path=/`.
- Every HTML page escapes all interpolated values (`& < > " '`).
- Commands: `npm test`, `npm run typecheck`, `npm run build`. Time-dependent tests use `vi.useFakeTimers({ toFake: ['Date'] })` + `vi.setSystemTime`.

## Review Focus

1. A client registers with `client_name` `<script>alert(1)</script>`: consent and `/clients` pages must show it as text, never markup. Test in Task 5 and Task 6.
2. The Google callback is hit with an unknown, expired or already-used `state` (back button, bookmark, replay): a 400 error page, no crash, no grant. Test in Task 5.
3. Google returns the email in different case (`Owner@Example.com`) than `MCP_OAUTH_ALLOWED_EMAILS` (`owner@example.com`): accepted. Test in Task 4.
4. `MCP_PUBLIC_URL` is given with a trailing slash (`https://saturn.brylex-it.dev/`): accepted and normalized; with a path (`https://x.dev/gsc`): rejected. Test in Task 1.
5. The server restarts between a token being issued and used: access and refresh tokens keep working, because the store reloads its hashes from disk. Test in Task 2.

- Produces (`provider.ts`):
  ```ts
  export type GoogleReturn =
    | { kind: 'consent'; consentId: string; csrf: string; clientName: string; redirectHost: string; expiresOn: string }
    | { kind: 'session'; email: string }
    | { kind: 'redirect'; url: string }            // e.g. access_denied back to the client
    | { kind: 'error'; status: 400 | 403; message: string };
  export class GscOAuthProvider implements OAuthServerProvider {
    constructor(o: { store: OAuthStore; google: GoogleSignIn; allowedEmails: string[]; ttlDays: number; logger: Logger })
    get clientsStore(): OAuthRegisteredClientsStore   // getClient/registerClient → store
    authorize(client, params, res): Promise<void>      // keeps request PENDING_TTL_MS, redirects 302 to google.authUrl
    startSessionSignIn(): string                        // Google URL for the /clients page
    handleGoogleReturn(q: { state?: string; code?: string; error?: string }): Promise<GoogleReturn>
    decideConsent(consentId: string, csrf: string, approve: boolean): { kind: 'redirect'; url: string } | { kind: 'error'; status: 400; message: string }
    challengeForAuthorizationCode(client, code): Promise<string>
    exchangeAuthorizationCode(client, code, verifier?, redirectUri?): Promise<OAuthTokens>
    exchangeRefreshToken(client, refreshToken): Promise<OAuthTokens>
    verifyAccessToken(token): Promise<AuthInfo>
    revokeToken(client, { token }): Promise<void>
  }
  ```
  All pending maps (authorization requests keyed by Google `state`, consents, codes) are single-use and expire after `PENDING_TTL_MS`. A code records the client id, redirect URI, PKCE challenge and grant id; it is deleted when exchanged.
